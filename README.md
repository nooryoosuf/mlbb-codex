# MLBB Codex

A complete, statically generated Mobile Legends: Bang Bang companion: every hero,
item, emblem and patch, with verified data and working build tools.

Built with Next.js 16 (App Router), React 19 and Tailwind CSS v4. Exported as a
static site and deployed to GitHub Pages.

## Routes

| Route | Description |
| --- | --- |
| `/` | Editorial home: hero of the day, roster overview, latest patch, tool entry points |
| `/heroes` | Hero catalogue with search, combined role/lane/favourite filters, sorting and grid/compact views |
| `/hero/[slug]` | Hero dossier: stats, ratings, skills with cooldowns, skins, matchups, related heroes and neighbours |
| `/items` | Item catalogue grouped by category with search |
| `/items/[slug]` | Item detail with stats and build context |
| `/emblems` | Emblems and talents |
| `/tools` | Tool index |
| `/tools/compare` | Side-by-side hero stat comparison (shareable `?a=&b=`) |
| `/tools/counters` | Counter/synergy explorer |
| `/tools/favourites` | Local favourites |
| `/tools/random` | Random hero picker with role/lane constraints |

`/builders` and `/knowledge` are kept as static meta-refresh redirects to
`/items` and `/emblems` so old links keep working.

## Data pipeline

The site has no runtime data fetching. Two sources are merged at build time:

- **MLBBDex API** (`https://mlbbdex.com/api/v1`) — base stats, skills, skins,
  splash art, items and patches. Wiki-derived content, licensed CC BY-SA.
- **Moonton GMS API** — skill icons, cooldowns/costs, skill tags, English lore and
  hero relations.

```bash
python scripts/fetch_mlbbdex.py   # cached fetch -> scripts/.cache/mlbbdex/
python scripts/build_dataset.py   # merge + download art -> src/data/*.json, public/
```

`fetch_mlbbdex.py` caches every response on disk and backs off on HTTP 429, so the
pipeline is safe to re-run. `build_dataset.py` writes:

```
src/data/heroes.json    134 heroes, 586 skills, 1062 skins, relations, lore
src/data/items.json     102 items with stats and icons
src/data/patches.json   276 patches
public/heroes/          <slug>.webp portraits (240x390)
public/splash/          <slug>.webp splash art (1280x720)
public/assets/items/    <slug>.webp item icons
```

Emblems and talents come from `src/data/builders_data.json`, generated by:

```bash
python scripts/scrape_emblems.py
python scripts/finalize_builders_data.py
```

Typed accessors (`getHero`, `resolveHero`, `getRelatedHeroes`, `getHeroOfTheDay`,
`formatStat`, `statRange`, …) live in `src/data/index.ts`. The JSON is cast through
`unknown` once there; everything above it is typed.

## Development

```bash
npm install
npm run dev      # http://localhost:3000
npm run lint
npm run build    # static export -> out/
npm start        # serve out/ on http://localhost:3000
```

Because the project uses `output: "export"`, `next build` writes a fully static
`out/` directory and `next start` is replaced by a static file server.

## Deployment (GitHub Pages)

`.github/workflows/deploy.yml` builds and deploys on every push to `main`:

- `NEXT_PUBLIC_BASE_PATH=/mlbb-codex` — project-site base path
- `NEXT_PUBLIC_SITE_URL=https://nooryoosuf.github.io/mlbb-codex` — canonical URLs,
  sitemap and robots

Local artwork is loaded through `asset()` in `src/lib/base-path.ts` so plain
`<img>` paths also receive the base path. `public/.nojekyll` keeps Next's `_next`
directory from being ignored by Jekyll.

To preview the exact Pages build locally:

```bash
$env:NEXT_PUBLIC_BASE_PATH="/mlbb-codex"
npm run build
```
